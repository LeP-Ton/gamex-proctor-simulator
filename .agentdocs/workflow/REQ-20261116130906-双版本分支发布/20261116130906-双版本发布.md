## 关键决策

- GitHub Pages 同一站点只保留一份当前产物，因此不能让两个分支各自单独部署。main 每次同时构建两版，输出根选择页、`illustrated/`、`realistic/`，再单次上传部署。
- 构建开始把两个分支解析为 40 位固定 SHA，分别检出、安装依赖、运行自身测试和构建。`manifest.json` 记录分支、提交、入口与保存键，避免构建中分支前移导致混版。
- 版本分支只用薄工作流请求 `workflow_dispatch main`，实际部署上下文始终为 main，兼容 `github-pages` 环境的部署分支策略。它们不直接持有 Pages 部署权限。
- 两版都成功后才组装和发布；本地组装先写暂存目录，完整验证后事务式替换输出。任一输入缺失或资源不适合子路径时保留原输出。
- Vite 使用现有相对资源地址。旧根目录 `?v=...` / `?debug=...` 书签进入写实版，查询和片段完整保留；普通根路径显示版本选择页。
- 两个应用在同一 origin，下一级目录不会隔离 localStorage。插画版改用 `gamex-proctor-illustrated-v1`，写实版保留 `gamex-proctor-v1`；不把新版存档交给旧界面解析，也不改写写实原档。

## 主要文件及影响

- `.github/workflows/pages.yml`：main 唯一组合发布者，锁定两版 SHA、各自测试构建，统一上传与部署。
- 两游戏分支的同名薄工作流：只请求 main 发布；插画分支 `src/storage.ts` 使用独立保存键。
- `scripts/build-pages.mjs`：验证并组装完整站点，生成 `manifest.json`、根 favicon 与 `.nojekyll`。
- `sites/index.html`、`style.css`：两个可玩版本的选择页和旧书签兼容跳转。
- `tests/pages.test.mjs`、`pages-browser.mjs`：组装失败不覆盖、相对资源、双入口、真实交互和同源存档隔离。
- `AGENTS.md`、README 与需求索引：长期分支职责、启动方式和本次权威入口。

本次只影响分支维护、发布入口、插画存档命名与部署适配，不更改游戏规则、事件计划或写实渲染。
