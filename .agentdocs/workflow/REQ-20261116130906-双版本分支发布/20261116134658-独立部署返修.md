## 独立工作流

- 每个 `.github/workflows/pages.yml` 只响应自己的版本分支；不请求原仓库 main，不读取或构建另一版本。
- 先 `npm ci`、本版 `npm test` 与 `npm run build`，再上传本版 `dist/` 并部署。
- 以仓库全名和分支全名保护 build/deploy 条件，避免该模板被复制到原仓库时误部署；原仓库后续可只运行测试和构建。
- 每个仓库的 Pages 部署环境仅允许本仓库该版本分支；权限分别限于构建 `contents:read/pages:read`、部署 `pages:write/id-token:write`。
- 独立镜像同步脚本限制两个目标仓库，拒绝私有/非预期仓库和未知远端 HEAD，创建快照子提交后以非强制方式推进对应 ref，不重写远端历史；凭据只由已登录 `gh` 使用，不保存或打印。

- `{illustrated,realistic}-live-{1440,1280}.png`：独立线上截图。
- `{illustrated,realistic}-pages.yml`：已成功运行的独立发布模板。
- `sync-independent-pages.mjs`：后续只同步指定版本的安全脚本；`{version}-state.json` 为非敏感远端 HEAD 和已上传 blob 缓存，需一并保留。

更新写实版时先将源码提交同步到原权威版本分支，再执行：

```sh
node scripts/sync-independent-pages.mjs realistic <完整源码SHA>
```

可复用脚本位于 main 的 `scripts/sync-independent-pages.mjs`，默认从脚本位置解析源码根目录、状态写入忽略的 `artifacts/independent-pages/`，不包含个人绝对路径。可设置 `PROCTOR_SOURCE_DIRECTORY` 指定原源码 checkout，以及 `PROCTOR_PAGES_STATE_DIRECTORY` 指定忽略目录中的持久状态路径。更换状态路径时先复制已验证的两个 state 文件；缺失状态或远端存在其他提交时脚本停止，不自动接管未知历史。
